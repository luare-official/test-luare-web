# C-02 / C-05 | 料金PDF請求・安全な自動送付 設計案 v0.2（2026-10-23）

## 2026-10-23 承認済みの送信方式：A案（優先仕様）
**ユーザー決裁済み：メール確認後、PDFをメール添付で送付し、確認後の完了画面からも期限付きでダウンロードできる。** この決定は方式だけであり、料金PDF・送信メール文面・個人情報の扱い・配信業者・実送信の開始は未承認のまま。

1. お客様が会社名・お名前・メール・同意を入力し、資料請求する。
2. システムが確認メール（PDFなし）を送信し、「メールをご確認ください」と表示する。
3. お客様がメール内ボタンを開き、確認を完了する。企業メールのリンク自動アクセスで認証が誤確定しないよう、単にリンクを開くだけではなく遷移先で確定操作を要求する安全設計を推奨。実際の操作はメールのボタン＋確認画面のボタンの約2クリック。会員登録・パスワード・6桁コード入力は不要。
4. 確認完了後、PDF添付メール（2通目）を送り、同時に認証済みの完了画面で期限付きの「PDFをダウンロードする」を表示する。公開HTMLやGitHubにPDFを置かずprivate R2からWorkerが配信する。
5. 確認リンク・画面でのダウンロード権限には短い有効期限と再利用対策を設定。再送には回数制限と重複メール防止を設定し、送信失敗時は適切なエラーを出す。メールリンクの自動先読みが認証を勝手に完了させないようにする。
6. お客様向けの通常メール数は1件につき2通。料金PDFの版・期限・プライバシー文言・確認/送付メール本文等はC-06/C-07と決裁事項D-06〜D-08で確定するまで送信機能を無効にする。

### A案の運用費用・利用量
- **小規模利用ならインフラ月額$0で開始できる可能性**があるが、超過・導入・運用工数を含まない。Cloudflare Workers Free $0（100,000リクエスト/日）、R2 Standard無料枠10GB-month、D1の無料枠（5GB等）、Turnstile Free $0、Resend Freeは3,000通/月かつ100通/日。
- A案は1請求につき通常2通。月30件→60通、月100件→200通、月1,000件→2,000通。**1日に51件以上**の確認完了が発生すると2通ずつなら100通/日の上限に達する。再送・通知メールでも枠を使う。
- 有料例：Resend Pro $20/月（50,000通/月）、Workers Paidは最低$5/月。初期構築・保守、DNS/ドメイン、PDFのサイズ、為替、税などは別。価格は各サービスの公式ページで2026-10-23確認、適用条件と費用上限は契約前に再確認。
- https://resend.com/pricing / https://developers.cloudflare.com/workers/platform/pricing/ / https://developers.cloudflare.com/r2/pricing/ / https://developers.cloudflare.com/d1/platform/pricing/ / https://developers.cloudflare.com/turnstile/plans/

## 要件と禁止事項
- サイトには料金の金額を一般公開しない。ご主人のr5試算は正式料金ではない。
- フォーム入力後、承認済みの料金PDFを申込者本人のメールへ送ることを目標とする。
- 料金・税区分・有効期限・送信文・差出人・個人情報の利用目的・保管期間・送付方式の決裁までは配信停止。
- PDF本文・APIキー・リスト・個人情報を公開GitHub/ブラウザ用JavaScript/公開Google Sheetに置かない。
- 顧客・営業先への試験メール禁止。利用可能なテスト用メールボックスが明示されない間、外部メール送信機能はOFF。

## C-02 ユーザーの流れ
1. トップページおよび各サービス詳細の「料金資料をメールで受け取る」リンク（設置場所はデザイン承認後）。既存の「無料相談」とは分ける。
2. 専用の `/pricing-request` 画面を開く（URLは案）。「送信いただいたメールアドレスに資料をお届けします」「内容は見積条件により変動」の説明（文面承認待ち）。
3. 最小入力フォーム：会社名（必須、1〜100字）、担当者氏名（必須、1〜80字）、会社メールアドレス（必須、形式検査、254字以内）、関心サービス（任意、選択肢）、ご相談・希望内容（任意、最大1000字）、利用目的・プライバシーポリシー同意（必須、チェックボックス）。
4. 意図しない連投を防ぐため、送信中の二重タップを防止。エラーは読み上げ可能に表示し入力内容を維持。
5. Server側受理後は「申込を受け付けました。メールが届かない場合は迷惑メール等をご確認ください。」を表示。未配信時の問い合わせ導線を用意。外部メール送信の成否を画面で過剰に開示しない。
6. 配信メールにPDFを添付する案を第一候補とする。送信メールの件名・本文・Reply-ToはC-07で承認。
7. フォームの自動送信と「後日営業案内を受け取る」は別目的。販促の同意は独立した任意欄として、ユーザーの承認まで設けない。

## UI/フォーム観点
- SPは一列、ボタンは幅広・指で押しやすく、現在の配色/書体を参照するが現行トップには手を入れない。
- `<label htmlFor>` / `id`を正しく紐付け、必須表示、`autocomplete`, `inputMode`, `aria-describedby`, `role=alert`とフォーカス移動を設計。
- 会社のメールのみという規則は強制できないため、個人メール利用をどう扱うかは運用判断。構文的妥当性と実在性を区別する。
- 入力値・メール・電話・問い合わせ内容をURLのクエリ文字列・GAイベントに含めない。

## C-05 推奨構成（暫定）
```text
[GitHub Pages/Next.js静的ページ]
  └ HTTPS POST /api/pricing-request (外部Workerエンドポイント)
    └ [Cloudflare Worker] ← Turnstile Siteverify (サーバーで検証)
          │ Origin/CORS制限（認証代替とはしない）
          │ 文字数・形式・サイズの検証 / 不正入力拒否
          │ 回数制限・送信重複防止 (D1など)
          │ 配信スイッチ SEND_ENABLED=false 初期値
          ├ [Cloudflare R2 private]  承認済みPDFのみ（公開URLなし）
          └ [Resend Transactional Email]  検証済み差出人ドメイン
                └ 受取人へPDF添付メール
```
- Workerの送信APIキー/Turnstile秘密キー/R2認証はWorkersのSecretsとプライベートバインディングで管理。公開GitHub、`NEXT_PUBLIC_*`、HTML、GitHub Actionsログへ書かない。
- R2は非公開バケットに承認済みPDFを保存。PDFを送る場合はWorkerがプライベートに読み込み添付データとして送信。PDFをWeb公開しない。
- メールサービスはResendを第一候補。送信ドメインはDNSでSPF/DKIM/DMARCを検証。添付ファイルの上限、送信ドメインとデータ保管条件は導入時に再確認。
- 送信エンドポイントは本番ローンチまで `SEND_ENABLED=false`。テストでは `TEST_MODE=true` 且つサーバー側の明示allowlistに一致する宛先だけを受け付ける。テストのメール送信先は顧客・営業先を含めない。
- Turnstileは必ずサーバー側のSiteverifyへ照会。加えてIP由来の個人情報をむやみに記録せず、短期のハッシュキー等で回数制限を検討する。
- 同じ申込ID/同じ宛先の短時間再試行に対して重複添付送信を防止。障害からのリトライは冪等性と送信履歴をもとに管理し、二重配信を避ける。
- PDF原本の差し替えは版数付きで行い、承認記録・版・失効タイミングを管理。承認前のdraftが配信されないようにする。
- 配信失敗・遅延は管理者に最小限の通知、個人情報の本文を管理チャネルに複製しない。メールの開封追跡は原則無効から開始。
- Webhookで配信状況を受ける場合は署名検証を必須とする。問い合わせ本文を大量にログへ残さない。
- 「入力しただけで即PDF」案は最短だが、第三者が他人のアドレスを入力する迷惑送信リスクが残る。**本人確認リンクを1回クリック後にPDF送付**する二段階案も比較し、事業側が選択する。

## 失敗と安全動作
| 状況 | 期待処理 |
| --- | --- |
| 入力不正・チェック未同意 | 送信せず項目ごとにメッセージ |
| Turnstile失敗 / BOT | 送信せず再試行案内、悪用防止 |
| 過剰アクセス / 同一申込重複 | 429等・レート制限、既存結果を返す、配信0〜1通 |
| PDF未承認 / R2に無い / APIキー未設定 | **fail closed（送信ゼロ）**、管理者調査へ |
| Resend障害 / タイムアウト | 二重送付しない範囲で再試行、受信者向け案内 |
| PDF有効期限切れ | 配信停止し管理者に新承認を依頼 |
| 添付が制限超過 | 配信しない、別の限定配布方法を設計・承認 |
| 宛先判定不能 | サーバー側のテストモードで停止 |
| 承認前に実行 | SEND_ENABLED=false → 送信しない |

| 項目 | 少量運用での目安 | 超過時 |

## 要承認（D-06〜D-08）
1. PDF内容・料金設定・税区分・見積条件・版管理（ユーザー＋ご主人）。
2. Worker / Resend / R2 の利用、運用アカウントと費用上限、ドメイン設定、担当者（ユーザー）。
3. 「即時PDF添付」か「本人確認を1回挟む」か（ユーザー）。
4. メール件名・本文・差出人・返信先と配信失敗時の窓口（ユーザー）。
5. 個人情報の収集目的、ポリシーURL、データ保存先・期間・削除手続・海外移転要否（法務・ユーザー）。
6. QA専用の送受信テストメールボックス（ユーザー）。指定まではメール送信0件。
