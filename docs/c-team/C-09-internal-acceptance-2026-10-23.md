# C-09 横断QA受入基準（2026-10-23 新方針）
C班と司令塔の内部テストに使用する。デザイン承認の正本はユーザーが承認済みの**HTML**。ブラウザで本番公開版を後から微修正する方針。
## ゲート1：差分レビュー（各班）
- 各班の承認HTMLとNext.js実装の画面キャプチャをPC 1440×900／モバイル390×844と360×800で比較。
- 構造、見出し、文言、配色、余白、書体、hover/touch展開、トランジション、スクロール、固定UI、reduced motionを確認。
- 「デザイン差分ゼロ」と表記するには両画面の比較証跡が必要。できない場合は未実施とする。
- 司令塔に実装版を提出するたびにユーザーへ再承認を求めない。
## ゲート2：機能（C班）
- `npm ci && npm run build` で静的成果物生成。GitHub PRのCI結果、コミットSHA、失敗ログを記録。
- `node scripts/qa/c09-static-export.mjs` で24リンクのトップページ出力／全ターゲットHTML／hash anchor／代表的ルート／一部SEO／秘密混入を機械検証。
- PC/SPで24リンクをすべてクリックし着地点・戻る・フォーカス・fixed headerを確認。CIのHTML検査はクリック検査の代替ではない。
- 連絡フォームは送信しないまま必須/形式/エラーメッセージ/完了UIを確認。サーバー連携テストは承認済みテスト用アドレスのみ。
- キーボード操作、フォーカス可視化、label/id、色コントラスト、画面読み上げ（可能な範囲）、mobile horizontal overflowを確認。
- robots、sitemap、canonical、OGP、hreflang、`html lang`を実URLとsourceで点検。
## ゲート3：機密・承認（司令塔）
- 料金金額、顧客情報、プロフェッショナル表記、個人情報ポリシーとメール送信機能について承認前の外部公開を不可とする。
- APIキー、メール送信キー、PDF正式原本、テスト先allowlistを公開Github/HTML/GA/Actionsログへ出さない。
- PRを班branchに作る。本番main mergeは司令塔のみ。C班は他班ソースと共通UIを直さず、課題を別途報告する。
